ROUNDTABLE AGENT HARNESS

让讨论收敛成
能签字的结论

不是又一个聊天机器人。它把 多角色多轮讨论 → 七段决策卡 → 独立验收 → 工单闭环 串成一条可审计的链路， 让一次项目评审从「开几天会」压缩成 几分钟出一页可签字的结论。

坐法 A · 单人主导现在在跑
入口是智能组建：丢一句想法或一份文档，AI 先审题三步（核心问题 / 视角 / 盲区），再按议题配角色槽位、配维度、配轮数——不是固定 4 个机器人。37 个实跑会话、136 个角色槽位都是这么开的。
坐法 B · 多人多 Agent 协同待启用
角色名就是真实岗位：每个岗位的人带自己的 agent 接入同一会话，identify 自称身份、join_context 加入，自己 claim_turn 说自己的话。谁会说什么，由那个人自己负责。
共同底座 · 每个角色开口前，系统先把这五样摆到它面前 准则硬规则 · 会话记忆 · 技能库目录 · 行业上下文 · 议题事实基准（带来源 URL 与发布日期）——不是让模型凭记忆瞎猜，是把材料摊开。喂什么，就决定它吐什么。

FROM REAL SESSIONS

三条不是设计出来的，是跑出来的

下面每一句都是从真实会话里原样摘的，不是我事后总结的漂亮话。

①先喂真数据，再谈结论

「基本面参考成都统计局公报：2025 年 11 月社零单月同比 -2.9%……8 万元投入必须算清回本周期。」 rt-chengdu · 运营角色 R1
「"降人力 60%"先给出处：成都统计局公报和公共数据开放平台都没有这个口径，只能算供应商话术。」 rt-chengdu · 全局批判角色 R1
「单店模型仍是 8 万÷12 店 = 6,667 元/店/年、556 元/店/月；回收期 = 8 万÷年化可核验现金流入，“省 1 小时”一律不进分子。」 rt-chengdu · 投资角色 R3
「公报只有社零与品类增速，没有任何客诉敏感性指标……拿宏观零售数据做微观客诉归因是无源断言，请撤下或标待查证。」 rt-chengdu · 全局批判角色 R6
喂进去的东西决定吐出来的东西。灌的是统计公报，它才敢把“降 60%”打成“话术”； 灌的是营销稿，它就只会复述营销稿。更狠的是第二条：喂了真数据，也不许乱引申——数据只能支撑它够得着的那一步。

②它敢反驳你的议题

「部分接受，但我要先反驳议题本身：把"做不做"和"唯一优先"捆成一个二选一，讨论就被拖到预算、开关上，没人回答最该先答的一句。」 rt-audit · opencode R1
「这个议题被设成二选一，本身就是战略上的偷懒——真正要定的是实施边界，不是实施与否。」 rt-gate · opencode R1
「这个议题连客户细分都没定。按 Osterwalder 九要素，价值主张必须先绑定客户细分……没定就敢报 3.5 天，等于给一个未定义物估价。」 rt-gate · opencode R1
「必须换」这个前提不成立。……瓶颈不在容量，而在"无写锁并发"和"无事务的半更新崩溃态"——这是代码缺陷，不是介质缺陷，换库治标不治本。 rt-store · 工程 R1
它不是帮你论证，是先问你这题该不该这么问。“必须换”这种前提，它敢直接回“前提不成立，这是代码缺陷不是介质缺陷”—— 一个只会点头的 AI，是查不出“问法本身在偷懒”的。

③最开放的题，出口也得是“能开工的决定”

最开放的题
rt-game2/3 是“罗小黑·众生之门”——纯创意题。21 / 32 条跑完，出口不是一堆点子，是「30 分钟单机垂直切片、3-5 扇门、不做开放世界」，第 5 轮就收敛。
批判角色原话
「把番剧里'想见另一侧的自己'当玩家动机，是本次讨论最大的未验证前提——那是观众情感，不是游戏动机，没有证据表明它能迁移进操作循环。」
裁决原话
「无规格单不拨款；50% 仅作五档预算下限、不参与设卡；效应量以置信区间刷新。」
为什么收敛
七段决策卡 + 双层判据要求有数字、有来源、有“若…则”——发散创意根本过不了闸。拼的不是点子多少，是每个数字都能查到出处；头脑风暴它不如你，把风暴压成一条能开工的路线，它比你狠。
WHAT'S UNDER THE HOOD

这三个问题，只有代码能答

面试官最会问的三句是：“多 Agent 是真接进来，还是循环调 API？”、“证据约束靠 prompt 还是靠代码？”、“反驳是不是你写死的？” ——下面是我翻自己代码之后的答案，包括对我不利的那部分。

①多智能体是真接，还是循环调 API？

真有协议
@modelcontextprotocol/sdk 1.10.2 + SSE / StreamableHTTP 双传输，33 个工具在 createMcpServer() 里真注册——外部 agent 能连上，不是“我用了 MCP”的口号。
它怎么说话
join_context 加入 → list_pending_turns 领到自己的题 → 自己读整份会话 → claim_turn 提交自己的话。不是被喂 prompt 代答。
现在的答案
136 个角色槽位 backend 全是 http，0 个外部 agent 真实接入——11-25 CLI 免费档全挂，我写死了 backend:"http"。所以它是“多模型扇出”，不是“多 agent 接入”。
边界
接入层是通的，放开外部 agent 只需一行配置。难的是先承认它此刻没开着，而不是拿协议名当卖点。

②证据边界：prompt 定规矩，代码当闸门

第 1 层
prompt（软）：准则文件 jury-guidelines v1.5 的测算纪律——宣称数字必去水、隐性成本必"若…则"、人工对标必给。这层模型可以不听。
第 2 层
代码（硬）：auditHardGates() 正则查七段齐不齐、有无数字、有无来源标记、隐性成本有无"若…则"、禁"整体良好/建议采纳"；checkCardArithmetic() 把卡里算式真求值（≈容差 5%）。不过就打回重写，≤2 轮，还不过打 ⚠️ 交 Boss。
第 3 层
独立判：独立验收角色按议题类型动态选角（投资类→独立审计师，运营类→一线店长），只判通过/不通过，附 3-5 条致命漏洞。
行业基准
industry-context.md v1.0.1 按 base 分段注入：workbuddy→PMBOK/GB-T 19001，auditor→COSO/ISO 31000，opencode→Osterwalder/波特五力。只收国标、法规、权威框架，明令禁写“行业经验之谈”；自定义角色只给事实纪律、不给数字。
所以
模型说“我觉得够了”不算数，正则和算式才算。软约束兜不住的地方，用代码兜——这是它能签字的原因。

③"敢反驳议题"是长出来的，不是写死的

查了什么
全库搜"议题本身""该不该这么问"这类字样，只有 1 处命中，还是组建准则里的"审题三步"——没有任何一条指令让角色槽位反驳议题。讨论 prompt 只写"明确表示认同或反驳、要有实质交锋"，反驳谁、反驳到哪一层，模型自己选。
所以场场不同
rt-gate 砍设问结构（"二选一本身就是战略上的偷懒"）；同一会话另一轮砍客户细分未定（"没定就敢报 3.5 天，等于给未定义物估价"）；rt-store 砍前提（"必须换这个前提不成立，是代码缺陷不是介质缺陷"）。模板写不出四种刀法。
也不场场有
rt-chengdu、rt-food、rt-ice 三个会话实例里没出现"反驳议题"——如果是预设，它该场场来一句。
最硬的自证
准则文件里留着一条翻车记录：“2026-11-24 游戏场，4 个角色把'游戏创意'审成'十年期 AI 技术立项'，16 条发言 16/16 落在 ROI/技术栈，游戏本体零评审——不是模型差，是组建没有审题环节”。这条规则是翻车后补的。如果我一开始就写死，就不会有这次翻车。

诚实边界（先说自己的短板）

① 不训练、不微调模型，智能全部来自自备 API key；
② 单机单进程，适合一个团队评审，不是全公司 SaaS；
③ 审计是应用级留痕，不是法律级存证；
④ 当前不做自动联网检索，事实靠半自动注入白名单；
⑤ 产物体（artifact）不进角色 prompt，外部 agent 得自己 get_artifact 取。

竞品卖「更聪明的讨论」，
它卖「能签字的结论」。
生成完就结束的 AI 很多；
敢打回重做的，很少。
